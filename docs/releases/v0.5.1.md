# dqt v0.5.1 — Release Notes

_Released: 2026-05-12_

## Summary

Nightly CI integration-test workflow for all warehouse adapters. Postgres and ClickHouse
run unconditionally via testcontainers; Snowflake, BigQuery, and Databricks are
credential-gated and skipped by default until repository secrets are configured.

## What's new

### CI — `.github/workflows/integration-tests.yml`

A new nightly workflow (schedule: `0 2 * * *`, also manually dispatchable) runs the
adapter test suite per engine in parallel jobs:

| Job | Trigger | Test file |
|---|---|---|
| `postgres` | Always | `tests/adapters/test_postgres_adapter.py` |
| `clickhouse` | Always | `tests/adapters/test_clickhouse_adapter.py` |
| `snowflake` | `DQT_SNOWFLAKE_ENABLED=true` | `tests/adapters/test_snowflake_adapter.py` |
| `bigquery` | `DQT_BIGQUERY_ENABLED=true` | `tests/adapters/test_bigquery_adapter.py` |
| `databricks` | `DQT_DATABRICKS_ENABLED=true` | `tests/adapters/test_databricks_adapter.py` |

### New adapter test files

- **`test_clickhouse_adapter.py`** — testcontainers-based, covers health_check, list_schemas,
  list_tables, describe_columns, sample, aggregate.
- **`test_snowflake_adapter.py`** — credential-gated, covers full adapter surface + cost-guard
  enforcement (`max_bytes_per_query=1` must refuse large queries).
- **`test_bigquery_adapter.py`** — credential-gated, covers dry-run cost guard.
- **`test_databricks_adapter.py`** — credential-gated, covers read-only enforcement.

All test files use `pytest.skip()` to gracefully no-op when credentials or optional
dependencies are absent — they never fail in environments without the secrets.

### README — adapter integration test documentation

Added "Adapter integration tests" section to README listing the enable variables and
secrets required per adapter.

# dqt v0.5.2 — Release Notes

_Released: 2026-05-12_

## Summary

Per-detector cost estimation and budget-aware suite execution. Every detector now exposes
`estimate_cost()` so callers can predict warehouse spend before running checks.
`Runner.run_suite()` uses those estimates to sort checks cheapest-first and skip any
check that would exceed the configured budget.

## What's new

### `CostEstimate` — `dqt.algorithms._base`

New dataclass exported from the top-level `dqt` namespace:

```python
@dataclass
class CostEstimate:
    rows_scanned: int
    warehouse_cost_usd: float   # 0.0 for local/DuckDB execution
    wall_time_seconds: float
```

### `BaseDetector.estimate_cost(row_count, sample_n=100_000)`

Default implementation assumes local DuckDB execution (zero warehouse cost).
Wall time is estimated at ~50k rows/sec:

```python
rows = min(row_count, sample_n)
CostEstimate(rows_scanned=rows, warehouse_cost_usd=0.0, wall_time_seconds=rows * 2e-5)
```

`BaseAggregateDetector` overrides this to return near-zero cost (single SQL aggregate,
0.1s wall time) since aggregate detectors push a single query and do no local computation.

Warehouse-push adapters (Snowflake, BigQuery) can override `estimate_cost()` to return
non-zero `warehouse_cost_usd` reflecting actual bytes-billed estimates.

### `SuiteResult` — `dqt.runner.runner`

New dataclass exported from the top-level `dqt` namespace:

```python
@dataclass
class SuiteResult:
    ran: list[RunResult]
    skipped: list[tuple[Check, str]]   # (check, human-readable reason)
    budget_spent_usd: float
    budget_total_usd: float
```

### `Runner.run_suite(checks, adapter, cost_budget_usd=10.0)`

Runs multiple checks in cost order with automatic budget enforcement:

1. Estimates cost for every check via `estimate_cost()`.
2. Sorts checks cheapest-first by `warehouse_cost_usd`.
3. Runs each check; accumulates `budget_spent_usd`.
4. Skips any check whose cost would push cumulative spend past `cost_budget_usd`,
   recording it in `SuiteResult.skipped` with a human-readable reason string.

```python
runner = dqt.Runner(store=store)
result = runner.run_suite(checks, adapter, cost_budget_usd=5.0)
print(f"Ran {len(result.ran)}, skipped {len(result.skipped)}")
print(f"Spent ${result.budget_spent_usd:.4f} of ${result.budget_total_usd:.2f}")
```

Row counts are cached per `(schema, table)` pair within a single `run_suite()` call to
avoid redundant `describe_columns()` round-trips.

## Tests

`packages/dqt/tests/test_cost_model.py` — 8 new tests:

| Test | What it covers |
|---|---|
| `test_cost_estimate_dataclass` | Field access on `CostEstimate` |
| `test_base_detector_estimate_cost_default` | Default zero warehouse cost |
| `test_base_detector_estimate_cost_small_table` | `rows_scanned` capped at `row_count` |
| `test_aggregate_detector_estimate_cost` | Aggregate override returns near-zero cost |
| `test_all_registered_detectors_have_estimate_cost` | All 64 detectors expose `estimate_cost()` |
| `test_run_suite_runs_all_within_budget` | All-zero-cost suite runs all checks |
| `test_run_suite_respects_zero_budget` | Non-zero-cost check skipped when budget=0 |
| `test_suite_result_exported_from_public_api` | `dqt.SuiteResult`, `dqt.CostEstimate` accessible |

## Breaking changes

None. `estimate_cost()` is additive; existing detector subclasses inherit the default
implementation automatically.

```bash
pip install --upgrade dqtlib
```

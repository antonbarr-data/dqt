# v0.9.0 - 2026-05-13

## The credibility batch

### Item 4: Complete CLI smoke test coverage

`test_cli_smoke.py` now parametrizes over all 11 subcommands including
`healthcheck` and `prometheus-exporter`. New subcommands are automatically
covered on registration.

### Item 5: Failure-mode docs for all 64 detectors

Every detector now has a `## Failure modes and known limits` section with:
- Assumptions and applicability context
- Symptom + fix table for common failure patterns
- FPR calibration table per data shape (lognormal/normal/Poisson/Beta)
- Recommended threshold ranges per shape

Previously 38 of 64 were documented. Now 64 of 64.

### Item 6: Benchmark infrastructure

`examples/benchmarks/run_benchmarks.py` runs every registered detector against
six synthetic datasets (normal/lognormal/categorical, clean/drifted) and writes
`examples/benchmarks/results.csv`. The README auto-renders a grouped markdown
table. Run after each release to update public benchmark claims.

### Item 7: Live adapter test stubs

Four new test files, each skipped unless the relevant env var is set:
- `test_live_snowflake.py` - requires `DQT_TEST_SNOWFLAKE_DSN`
- `test_live_bigquery.py` - requires `DQT_TEST_BIGQUERY_PROJECT`
- `test_live_databricks.py` - requires `DQT_TEST_DATABRICKS_DSN`
- `test_live_clickhouse.py` - requires `DQT_TEST_CLICKHOUSE_DSN`

Each has 4 tests: health check, six-step verification, list schemas, sample DataFrame.
16 tests total; all collect and skip cleanly without credentials.

### Items 8-9: Quality dashboard + recipe cookbook

- `docs/quality_dashboard.md`: design spec and static HTML prototype for the
  public per-detector precision/recall dashboard (planned: dqt.dev/quality)
- `docs/recipes/`: 20 end-to-end scenario recipes with dqt check YAML, expected
  output, and statistical rationale

Recipe scenarios: SCD monitoring, bot traffic detection, revenue-by-segment,
migration from GX/Soda, schema alerting, A/B guardrails, churn early warning,
payment method drift, LLM wiki workflow, Snowflake/BigQuery cost-aware monitoring,
and 10 more.

### Items 10-12: Documentation pass

- `docs/statistical-primer.md`: extended with methodology design choices -
  why double-MAD over MAD, Wasserstein-1 over KS, PCMCI+ over bivariate Granger,
  BH-FDR over Bonferroni, E-values, STL+CUSUM combo, k=11.0 for heavy tails,
  bootstrap CIs. Each choice cites the canonical reference.
- `docs/when-not-to-use-dqt.md`: honest disqualification - managed services,
  real-time streaming, greenfield teams, SQL-only stacks, compliance requirements,
  static data.
- `docs/getting-started.md`: verified 5-minute guide against actual CLI code.

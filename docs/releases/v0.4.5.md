# dqt v0.4.5 — Release Notes

_Released: 2026-05-12_

## Summary

Floor 1 of the 78→101 quality ladder: twelve targeted improvements closing gaps in the library, CLI, dashboard, and test coverage. No breaking changes. The detector library, runner, and dashboard are now substantially more robust and better documented.

## What's new

### Features

- **`dqt demo seed` / `dqt demo reset`** — new CLI commands seed a local `demo/` directory with 500-row synthetic `fct_orders` and `fct_sessions` CSVs and a ready-to-run `checks.yaml`. Great for demos, CI smoke tests, and getting started in under a minute.
- **`dqt run --watch`** — continuous unattended monitoring mode: re-runs all checks on a configurable interval and streams verdicts to the terminal.
- **Dashboard incident list and detail views** — standalone `dqt dashboard` now shows a full incident list (`/incidents`) with severity, score, and opened-at timestamp, plus per-check incident detail at `/incidents/<check_id>`.
- **Dashboard lineage DAG** — `/lineage` now renders a d3 force-directed graph when a `lineage_graph` is passed to `build_app()`.
- **Dashboard causality review** — `/causality/review` accepts accept/reject decisions for proposed causal edges, persisted via `store.save_causal_review()`.
- **Dashboard token auth** — set `DQT_DASHBOARD_TOKEN` to protect all routes with RFC 6750 Bearer authentication. `/health` is always open.
- **OpenLineage integration** — `Runner.run()` now emits `START`, `COMPLETE`, and `FAIL` events to any configured OpenLineage backend, enabling cross-tool lineage tracking.
- **Benchmark infrastructure** — `benchmarks/run_benchmarks.py` measures precision/recall/F1/FPR for every univariate and drift detector against four synthetic fixtures (normal mean-shift, lognormal tail-shift, 5% outlier injection, 10% null injection). Output in [docs/benchmarks.md](../benchmarks.md).

### Fixes

- **IsolationForest univariate guard** — calling `IsolationForestDetector.fit()` on fewer than 2 numeric columns now raises `ValueError` with a clear message pointing to `ecod` or `lof` as the correct alternative. Previously it ran silently and produced meaningless scores.
- **Dashboard `_get_all_incidents`** — was reading the private `store._incidents` dict directly; now calls `store.list_all_incidents()` via the public protocol. `list_all_incidents()` added to both `ResultsStore` protocol and `MemoryStore`.
- **Dashboard causality review** — invalid `edge_id` (non-UUID) and invalid `decision` values now return HTTP 400 with a structured error instead of silently doing the wrong thing.
- **Dashboard lineage** — `lineage_graph` is now captured from the `build_app()` closure, not stored on `app.state`, matching how `store` is handled.
- **OpenLineage FAIL event** — `error_message` was not being passed through; now correctly included in the event payload.

### Tests

- **Property-based invariant tests** — `tests/property_tests/test_detector_invariants.py` uses Hypothesis to test every univariate detector against ≥30 random float inputs, verifying `DetectorResult` shape, finite score, non-empty `plain_english`, and `dict` details. Exception handling tightened from `except Exception` to specific types.
- **CLI smoke tests** — eight new tests in `packages/dqt-cli/tests/test_smoke.py` covering every subcommand (`version`, `demo seed`, `demo reset`, `run`, `run --help`, `demo --help`, `dashboard --help`).
- **Dashboard unit tests** — four new test modules covering incidents, lineage, causality review, and token auth.

### Documentation

- **Failure-mode analysis added to all 64 detector docs** — every `docs/algorithms/<slug>.md` now includes "When it works well", "When it fails / Limitations" (with minimum sample size and FPR at defaults for normal vs heavy-tailed data), and "Recommended thresholds by data shape".

## Breaking changes

None.

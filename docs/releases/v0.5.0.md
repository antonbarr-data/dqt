# dqt v0.5.0 — Release Notes

_Released: 2026-05-12_

## Summary

Property-based test coverage for all 64 detectors, plus removal of the deprecated
third-party EventSource adapters. Every detector invariant is now enforced by
Hypothesis on every CI run.

## What's new

### Tests — Hypothesis property-based coverage for all detectors

Four new test files add `@given`-decorated invariant tests for the 42 detectors that
previously lacked Hypothesis coverage:

- **`test_hypothesis_drift.py`** — `psi`, `kl_divergence`, `js_divergence`, `mmd`,
  `wasserstein_1`, `adwin`, `chi_square_drift` (23 tests)
- **`test_hypothesis_timeseries.py`** — `cusum`, `page_hinkley`, `holt_winters`
  (12 tests; `bocpd`, `prophet_anomaly`, `matrix_profile` skipped — optional deps)
- **`test_hypothesis_outliers.py`** — `grubbs`, `generalized_esd`, `auto_outlier`,
  `outlier_fraction_drift`, `lof`, `mahalanobis_distance`, `ecod`, `hbos`,
  `one_class_svm` (27 tests)
- **`test_hypothesis_misc.py`** — `null_fraction`, `string_case_violation`,
  `date_part_missing_fraction`, `freshness_seconds_behind`, `benford_law_fit`,
  `cramers_v`, `mutual_information`, `callable_check` (30 tests; `sql_assertion_violation`,
  `remote_check` skipped — require live connections)

Every non-skipped detector now asserts on every run:
1. `verdict in {pass_, warn, fail}`
2. `score in [0.0, 1.0]`
3. `plain_english` is a non-empty string
4. No `None` values among numeric `details` fields
5. No crash on empty input, all-NaN input, or constant (zero-variance) input

Total new Hypothesis tests: **92 passing, 5 skipped** (optional dependencies).

### Bug fix — MMD detector NaN score on constant reference data

`_median_gamma()` in `dqt/algorithms/drift/mmd.py` previously called `np.median` on
an empty array when the reference data was constant, producing `NaN` bandwidth that
propagated to a `NaN` score. Fixed by early-returning `gamma=1.0` when no non-zero
pairwise distances exist.

### EventSource cleanup — deprecated adapters removed

`AirflowEventSource`, `DagsterEventSource`, and `DbtCloudEventSource` were deprecated
in v0.4.7 with a v0.6.0 removal target. Since they are not wired into any active causal
math (see events.py comments), removing them now cleans up dead code and external HTTP
dependencies. The core `EventSource` protocol, `NullEventSource`, and `InMemoryEventSource`
are retained for internal testing.

Files changed:
- `packages/dqt/src/dqt/causality/events.py` — removed three deprecated classes and
  their HTTP helper functions
- `packages/dqt/src/dqt/causality/__init__.py` — removed from `__all__`
- `packages/dqt/tests/causality/test_events.py` — removed tests for deleted classes

### Test hygiene

- `test_public_api.py` — removed hardcoded version string assertion (`== "0.1.4"`);
  version is now checked only by pyproject.toml and CI.
- `test_hypothesis_timeseries.py` — added `deadline=None` to Holt-Winters Hypothesis
  settings; the STL/HW fitting step legitimately exceeds the 200ms default deadline.

## Breaking changes

`AirflowEventSource`, `DagsterEventSource`, and `DbtCloudEventSource` are removed.
Upgrade path: implement the `EventSource` protocol directly or open an issue.

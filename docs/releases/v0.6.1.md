# dqt v0.6.1 — Release Notes

_Released: 2026-05-12_

## Summary

Anomaly explanation per-incident via the causal layer. `explain_incident()` traverses
the lineage graph upstream from a failing check, collects score time-series from the
store, and runs Granger causality to surface the most likely upstream cause as
structured evidence.

## What's new

### `explain_incident(incident, checks, store, graph)`

```python
from dqt import explain_incident

explanation = explain_incident(
    incident,
    all_checks,
    results_store,
    lineage_graph,
    max_upstream_depth=3,
    min_history_runs=20,
)

if explanation:
    print(explanation.plain_english)
    for cause in explanation.causes:
        if cause.evidence_strength in ("strong", "moderate"):
            print(f"  -> {cause.upstream_node_id} "
                  f"(p={cause.granger_adjusted_p:.4f}, lag={cause.selected_lag})")
```

### `IncidentExplanation` dataclass

```python
@dataclass
class IncidentExplanation:
    incident_id: UUID
    failing_check_id: UUID
    failing_node_id: str
    causes: list[CausalEvidence]    # ordered: strongest evidence first
    plain_english: str              # human-readable summary
    n_upstream_checks_found: int
    n_upstream_checks_tested: int
```

### `CausalEvidence` dataclass

```python
@dataclass
class CausalEvidence:
    upstream_check_id: UUID
    upstream_node_id: str
    evidence_strength: str          # "strong"|"moderate"|"weak"|"none"|"insufficient_history"
    granger_adjusted_p: float | None
    granger_f_statistic: float | None
    selected_lag: int | None
    n_observations: int
```

### Algorithm

1. Resolve the failing check to a lineage node `{schema}.{table}.{column}`.
2. BFS upstream in `LineageGraph` up to `max_upstream_depth` hops.
3. Find checks monitoring each upstream node.
4. Load `RunResult` score history for all involved checks from the store.
5. Align time-series (newest-first; reversed for chronological order).
6. Run `granger_pairwise()` on the panel — each upstream score as cause,
   failing check score as effect.
7. Apply BH FDR correction. Classify edges as strong/moderate/weak/none.
8. Return causes ordered by evidence strength.

Returns `None` if the failing check cannot be found or resolved in the graph.
Returns an explanation with `evidence_strength="insufficient_history"` when fewer
than `min_history_runs` (default 20) run history points exist.

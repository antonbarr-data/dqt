# dqt v0.8.4 - Release Notes

_Released: 2026-05-12_

## Summary

Runner and store enhancements: filtered query API, dry-run mode, parallel
suite execution, adapter retries with graceful degradation, and a healthcheck
CLI command.

## What's new

### `store.query_runs(check_id, verdict, since, until, limit)`

Filtered query across runs on both `MemoryStore` and `PostgresStore`. All
parameters are optional; omitting them returns all runs up to `limit`.

### `Runner.dry_run(check, adapter)`

Returns the SQL that would be executed and a `CostEstimate` without touching
the store or running any detector.

### `Runner.run_suite(..., parallelism=N)`

Runs N checks concurrently via `ThreadPoolExecutor`. Default is 1 (serial).

### `Runner(max_retries=3, retry_delay_seconds=1.0)`

Retries on adapter `TimeoutError`/`OSError`/`ConnectionError` with exponential
backoff. After exhausting retries, returns `verdict=warn` and saves the result
to the store rather than raising.

### `dqt healthcheck`

CLI command that verifies dqt import, detector registry, `MemoryStore`
round-trip, and `ProofBundle` round-trip. Exits 0 on success, 1 on failure.

## Breaking changes

None.

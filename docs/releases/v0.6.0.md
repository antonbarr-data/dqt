# dqt v0.6.0 — Release Notes

_Released: 2026-05-12_

## Summary

Causal-aware alert deduplication. Given a set of concurrent open incidents and the
lineage graph, `deduplicate_alerts()` collapses chained downstream failures into a
single root-cause alert group — eliminating the alert storm that occurs when one
upstream failure propagates to N downstream checks.

## What's new

### `deduplicate_alerts(incidents, checks, graph)`

```python
from dqt import deduplicate_alerts
from dqt.lineage import LineageGraph

result = deduplicate_alerts(open_incidents, checks, lineage_graph)

for group in result.groups:
    notify_oncall(group.root_check_id)          # one alert per root cause
    for cid in group.downstream_check_ids:
        suppress_alert(cid)                     # skip the downstream noise

print(f"{result.n_root_causes} root causes, {result.n_suppressed} suppressed")
```

### `AlertGroup` dataclass

```python
@dataclass
class AlertGroup:
    root_check_id: UUID           # check that caused the cascade
    root_node_id: str             # lineage node id of the root
    downstream_check_ids: list[UUID]
    downstream_node_ids: list[str]
```

### `DeduplicationResult` dataclass

```python
@dataclass
class DeduplicationResult:
    groups: list[AlertGroup]
    unresolved_check_ids: list[UUID]   # checks not found in the lineage graph

    @property
    def n_root_causes(self) -> int: ...
    @property
    def n_suppressed(self) -> int: ...
```

### Algorithm

1. Map each `Incident.check_id` to a lineage node via `{schema}.{table}.{column}`
   (or `{schema}.{table}` when the check has no column).
2. Build a "failing nodes" set from all resolved incidents.
3. For each failing node, walk `LineageGraph.all_upstream()` — if any upstream node is
   also failing, this node is downstream and belongs to that upstream's group.
4. Nodes with no failing upstream are root causes. Each root gets one `AlertGroup`.
5. Checks whose lineage node is not in the graph are returned in `unresolved_check_ids`
   and never suppressed.

### Where to integrate

- **Server scheduler**: after a batch of check runs, call `deduplicate_alerts()` with
  all open incidents and the tenant's lineage graph. Route one notification per group.
- **CLI**: `dqt incidents deduplicate` (CLI wrapper, future).
- **WebSocket feed**: the live incident feed on `/incidents` can group incidents by
  `AlertGroup.root_check_id` for the same visual collapsing.

## Tests

`packages/dqt/tests/test_alert_deduplication.py` — 8 tests covering: single incident
is its own root, 3-node chain collapses to 1 root + 2 suppressed, two independent
failures stay independent, unresolved checks, table-level nodes (no column), public
API exports, and `DeduplicationResult` property helpers.

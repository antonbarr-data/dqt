# Lineage API

dqt builds column-level lineage from three sources: raw SQL (via sqlglot), dbt manifests, and OpenLineage events. All three produce the same `LineageGraph` model that feeds into `write_vault()` and the incident blast-radius calculation.

---

## LineageGraph model

```python
from dqt.lineage import LineageGraph, LineageNode, LineageEdge

graph = LineageGraph(nodes=[], edges=[])
```

### LineageNode fields

| Field | Type | Description |
|-------|------|-------------|
| `id` | `str` | Unique node identifier — e.g. `"gigler_transactions"` or `"weekly_transaction_volume"` |
| `kind` | `str` | `"dataset"`, `"column"`, `"metric"`, `"model"` |
| `label` | `str` | Display name |
| `meta` | `dict` | Optional — description, owner, domain, unit, etc. |

### LineageEdge fields

| Field | Type | Description |
|-------|------|-------------|
| `source` | `str` | Upstream node ID — format `"dataset.column"` for column-level, `"dataset"` for table-level |
| `target` | `str` | Downstream node ID |
| `kind` | `str` | `"causality"`, `"aggregates"`, `"filters"`, `"joins"`, `"derives"` |
| `confidence` | `float` | 0–1, defaults to 1.0 for parsed edges |
| `lag_weeks` | `int \| None` | Causal lag — only relevant for `kind="causality"` |
| `description` | `str \| None` | Human-authored description |

## Building a graph manually

```python
from dqt.lineage import LineageGraph, LineageNode, LineageEdge

graph = LineageGraph(
    nodes=[
        LineageNode(id="gigler_transactions", kind="dataset", label="Transactions"),
        LineageNode(id="gig_prices",          kind="dataset", label="Gig Prices"),
        LineageNode(
            id="weekly_transaction_volume",
            kind="metric",
            label="Weekly Transaction Volume",
            meta={"description": "Sum of completed transactions per week", "unit": "count"},
        ),
        LineageNode(
            id="marketing_campaigns",
            kind="dataset",
            label="Marketing Campaigns",
        ),
    ],
    edges=[
        # Column aggregates into metric
        LineageEdge(
            source="gigler_transactions.amount_usd",
            target="weekly_transaction_volume",
            kind="aggregates",
        ),
        # Causal edge: marketing spend → transaction volume (2-week lag)
        LineageEdge(
            source="marketing_campaigns.spend_usd",
            target="weekly_transaction_volume",
            kind="causality",
            confidence=0.72,
            lag_weeks=2,
            description="Acquisition spend drives transaction volume with 2-week lag",
        ),
        # Join dependency between datasets
        LineageEdge(
            source="gig_prices.avg_price_usd",
            target="gigler_transactions.amount_usd",
            kind="derives",
            description="Transaction amount normalised by category avg price",
        ),
    ],
)
```

## Parsing lineage from raw SQL (sqlglot)

dqt uses [sqlglot](https://github.com/tobymao/sqlglot) to extract column-level lineage from any SQL dialect.

```python
from dqt.lineage import parse_sql_lineage

sql = """
CREATE TABLE fct_revenue AS
SELECT
    t.transaction_id,
    t.amount_usd,
    t.buyer_country,
    p.avg_price_usd,
    t.amount_usd / p.avg_price_usd AS normalised_amount
FROM gigler_transactions t
JOIN gig_prices p ON t.gig_category = p.category
WHERE t.status = 'completed'
"""

graph = parse_sql_lineage(sql, dialect="duckdb")

for edge in graph.edges:
    print(f"{edge.source} → {edge.target}  [{edge.kind}]")

# gigler_transactions.transaction_id → fct_revenue.transaction_id  [derives]
# gigler_transactions.amount_usd     → fct_revenue.amount_usd      [derives]
# gigler_transactions.buyer_country  → fct_revenue.buyer_country    [derives]
# gig_prices.avg_price_usd           → fct_revenue.avg_price_usd   [derives]
# gigler_transactions.amount_usd     → fct_revenue.normalised_amount [derives]
# gig_prices.avg_price_usd           → fct_revenue.normalised_amount [derives]
```

### Supported dialects

Pass `dialect=` any sqlglot-supported dialect: `"duckdb"`, `"postgres"`, `"bigquery"`, `"clickhouse"`, `"snowflake"`, `"spark"`, `"mysql"`, `"trino"`. Omit for auto-detection.

### Parsing multiple SQL files

```python
import pathlib
from dqt.lineage import parse_sql_lineage, merge_graphs

graphs = []
for sql_file in pathlib.Path("raw/sql/").glob("*.sql"):
    sql = sql_file.read_text()
    graphs.append(parse_sql_lineage(sql, dialect="bigquery"))

# Merge into a single graph, deduplicating nodes and edges
full_graph = merge_graphs(graphs)
```

## Ingesting a dbt manifest

If your project uses dbt, point dqt at the `manifest.json` to get column-level lineage for free.

```python
from dqt.lineage import load_dbt_manifest

# manifest.json is generated by `dbt compile` or `dbt run`
graph = load_dbt_manifest("target/manifest.json")

print(f"Loaded {len(graph.nodes)} nodes, {len(graph.edges)} edges")

for edge in graph.edges:
    print(f"{edge.source} → {edge.target}")
```

### What dbt manifest ingestion extracts

- All `model` and `source` nodes become `LineageNode(kind="model")` and `LineageNode(kind="dataset")`
- Column-level `depends_on` becomes `LineageEdge(kind="derives")`
- `semantic_models.yml` metric definitions become `LineageNode(kind="metric")` with aggregation edges
- Test definitions are attached as node metadata (not edges)

### Merging dbt graph with manual causal edges

```python
from dqt.lineage import load_dbt_manifest, LineageEdge
from dqt.semantic import load_semantic_manifest
from dqt.lineage import write_vault

manifest = load_semantic_manifest("semantic.yaml")
graph = load_dbt_manifest("target/manifest.json")

# Append causal edges discovered via dqt or authored manually
graph.edges.append(LineageEdge(
    source="marketing_campaigns.spend_usd",
    target="weekly_transaction_volume",
    kind="causality",
    confidence=0.72,
    lag_weeks=2,
    description="From GTM-001 ticket: acquisition spend → volume, 2-week lag",
))

write_vault(manifest, graph, vault_dir="vault/", vault_title="My Knowledge Graph")
```

## Ingesting OpenLineage events

For non-dbt pipelines that emit [OpenLineage](https://openlineage.io/) events (Airflow, Spark, Flink):

```python
from dqt.lineage import load_openlineage_events

# Events can be a local NDJSON file or a list of event dicts
graph = load_openlineage_events("openlineage_events.ndjson")

# Or from a live Marquez API
graph = load_openlineage_events(
    marquez_url="http://localhost:5000",
    namespace="my_pipeline",
)
```

## Querying the graph

```python
# All upstream nodes for a given node
upstreams = graph.upstreams("weekly_transaction_volume")

# All downstream nodes (blast radius)
downstreams = graph.downstreams("gigler_transactions.amount_usd")

# Shortest path between two nodes
path = graph.path("marketing_campaigns.spend_usd", "weekly_transaction_volume")

# All edges of a given kind
causal_edges = [e for e in graph.edges if e.kind == "causality"]

# Nodes by kind
datasets = [n for n in graph.nodes if n.kind == "dataset"]
metrics  = [n for n in graph.nodes if n.kind == "metric"]
```

## Full pipeline: SQL files → vault

```python
import pathlib
from dqt.lineage import parse_sql_lineage, merge_graphs, LineageEdge
from dqt.semantic import load_semantic_manifest
from dqt.lineage import write_vault

# 1. Parse all SQL files in raw/sql/
graphs = [
    parse_sql_lineage(p.read_text(), dialect="bigquery")
    for p in pathlib.Path("raw/sql/").glob("*.sql")
]
graph = merge_graphs(graphs)

# 2. Append causal edges from raw/tickets/ analysis
graph.edges.extend([
    LineageEdge(
        source="marketing_campaigns.spend_usd",
        target="weekly_transaction_volume",
        kind="causality",
        confidence=0.72,
        lag_weeks=2,
        description="Acquisition spend drives volume (GTM-001)",
    ),
])

# 3. Load semantic manifest
manifest = load_semantic_manifest("semantic.yaml")

# 4. Write the vault
write_vault(manifest, graph, vault_dir="vault/", vault_title="Gigler Knowledge Graph")
```
